# Task Handoff：MarketPulse 第三期 — 阈值告警

> 复制到 `tasks/2026-09-01-marketpulse-phase3/prd.md`


## Goal

在现有日报基础上，增加**主动监控能力**：当 VIX/VXN/MOVE 的当日变化超过预设阈值时，**独立推送一条警报消息**到 QQ，让用户在市场异常波动发生时第一时间感知，而无需等待次日日报。

目标是实现"被动收日报 → 主动收警报"的升级，满足最初"市场突变时及时通知我"的需求。


## Current Understanding

### 现有基础

- `src/fetcher.py`：数据获取（已拆分）
- `src/analyzer.py`：状态分类、涨跌幅计算
- `src/reporter.py`：日报渲染（含趋势图）
- `daily_report.py`：收盘报告编排入口（Hermes 早8点触发）
- `snapshot_report.py`：午盘快照编排入口
- `data/history.json`：历史数据（每日一条）
- `data/last_values.json`：昨日值缓存（用于涨跌幅计算 + 告警基准）

### 已确认的设计决策（用户定稿，勿改）

1. **告警基准**：统一用 `data/last_values.json`（昨收缓存）作为对比基准。午盘快照为做告警判断需读取 `last_values.json`，但**只读、不写 history.json**。
2. **告警去重时序**："午盘触发则收盘跳过同一指数，午盘没触发则收盘正常判断"。即当日某指数在午盘已告警 → 收盘不再重复；午盘未触发 → 收盘可触发。用 `alerts.log` 记录当日已触发状态。
3. **默认阈值**：VIX ±20% / VXN ±20% / MOVE ±15%（表格为准）。环境变量示例 `ALERT_THRESHOLD_VIX=25` 表示"覆盖后的值"，旁边注释的"默认20"指未覆盖时的默认。

### 新增能力：阈值告警

**触发条件（默认阈值）**：

| 指数 | 阈值类型 | 默认阈值 | 说明 |
| :--- | :--- | :--- | :--- |
| VIX | 单日变化率 | ±20% | 变化幅度超过此值时触发 |
| VXN | 单日变化率 | ±20% | 同上 |
| MOVE | 单日变化率 | ±15% | 债市波动相对平稳，阈值略低 |

**触发时机**：

| 检查点 | 是否告警 | 说明 |
| :--- | :--- | :--- |
| 午盘快照（12:30） | ⚠️ 是 | 与昨收对比，若超过阈值则推送午盘警报 |
| 收盘报告（16:30） | ⚠️ 是 | 与昨收对比，若超过阈值且午盘未触发同指数，则推送收盘警报 |

**推送内容**：独立推送，与日报分开。示例：

```
🚨 市场警报：VIX 异常波动

当前值：26.40
昨日收盘：22.30
变化率：+18.4%
触发阈值：±20%

状态：已进入"警惕"区间（20-30）
建议：市场不确定性上升，请关注持仓风险。

查看完整日报：reports/2026-08-29.md
```


## Requirements

### 必须实现

1. **告警判断逻辑**（在 `analyzer.py` 中新增 `check_breach()`）
   - 输入：当前值、昨日值、指数名称、阈值配置
   - 输出：是否触发告警、告警级别（WARN/ALERT）、消息内容
   - 阈值可配置（环境变量或配置文件覆盖）

2. **告警独立推送**（复用 Hermes 渠道）
   - `daily_report.py` 和 `snapshot_report.py` 运行完毕后，检查是否触发告警
   - 若触发，生成告警文件 `alerts/YYYY-MM-DD-{type}.md`（type = noon / close）
   - **Hermes 侧负责检测 `alerts/` 目录并推送**（检测到告警文件即推送；Hersres cron 处理见"Hermes 侧配置"节）
   - 流程：先数据获取 → 生成报告 → 检查告警 → 写入告警文件

3. **告警去重**（`src/alerter.py` 职责）
   - 同一指数同一天只告警一次
   - 记录当日已告警状态到 `data/alerts.log`
   - 逻辑须满足决策 2（午盘触发 → 收盘跳过同指数）

4. **阈值配置**
   - 支持环境变量覆盖：
     ```bash
     ALERT_THRESHOLD_VIX=25   # 覆盖默认的 20
     ALERT_THRESHOLD_VXN=25
     ALERT_THRESHOLD_MOVE=18
     ```
   - 未设置时使用默认值（20 / 20 / 15）

5. **告警内容结构**
   - 指数名称 + 当前值 + 昨日值 + 变化率 + 阈值
   - 当前市场状态（平静/警惕/恐慌）
   - 简短建议（不超过 2 行）
   - 相关报告路径

### 必须保持

- 容错原则：告警逻辑失败不影响日报生成
- 测试全绿：新增代码需补测试
- 依赖不变：不新增第三方库
- 代码行数：告警相关代码 ≤ 150 行
- 不破坏现有功能：日报仍正常生成，告警作为独立通道

## Constraints

- **告警去重**：同一指数同一天只告警一次；午盘触发 → 收盘跳过同指数（决策 2）
- **告警基准**：统一用 `last_values.json`（决策 1）；快照只读缓存、不写 history
- **告警阈值**：默认 20/20/15，支持环境变量覆盖
- **推送方式**：Hermes 负责推送（沿用 QQ 渠道），脚本仅生成告警文件
- **执行顺序**：数据获取 → 生成报告 → 检查告警 → 写入告警文件
- **Hermes 侧配置**（非仓库项，交付时由 Hermes 落地）：
  1. 三期告警依赖二期的两条 cron（午盘快照 00:30 cron + 收盘早8点 cron）
  2. Hermes 每天早8点收盘 cron 在推送日报时，检测 `alerts/` 目录当日是否存在告警文件；有则**独立推送一条告警消息**
  3. 告警推送逻辑为三期交付的 Hermes 配置项，需在实现完成后与二期 cron 一并落地

## Risks

| 风险 | 应对 |
| :--- | :--- |
| 告警阈值设置过敏感，频繁触发 | 默认阈值 20% 已过滤日常波动；用户可自行提高阈值 |
| 同一指数午盘和收盘重复告警 | 通过 `alerts.log` 记录当日已告警状态，午盘触发则收盘跳过 |
| 告警消息与日报内容重叠 | 告警独立推送，日报完整呈现，两者不冲突 |
| Hermes 推送告警时消息过长 | 告警内容控制在 10 行以内，仅保留关键信息 |
| 快照误写 history.json | 决策 1 明确快照只读缓存、不写 history，实现时校验 |
