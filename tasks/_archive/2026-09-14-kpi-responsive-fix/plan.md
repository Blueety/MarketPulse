# 计划：KPI 卡响应式断点修复 + 验收脚本补中间宽度断言

- **日期**：2026-09-14
- **任务目录**：`tasks/2026-09-14-kpi-responsive-fix/`
- **触发**：需求方反馈「小尺寸屏幕上 KPI 挤在一起」——实测为**两段中间宽度区间被漏掉**
- **性质**：纯前端 CSS（`style.css`）+ 验收脚本增强（`verify_ui.py`）

---

## 1. 结论先行

**不是「小尺寸」问题，是 CSS 断点有两处空档，而现有验收脚本的三视口恰好跳过了它们。**

| 空档 | 区间 | 现象 | 实测最严重 |
|---|---|---|---|
| **A** | **1500–1919px** | 5 列 + 26px 字号，中间无任何断点 → 卡宽从 314 缩到 250，字号不降 | 1600 时 **2 张截断 4px** |
| **B** | **769–1024px** | 3 列 + 侧栏仍占 232px → 卡宽从 237 缩到 **152px** | 769 时 **4 张截断 85px**（三分之一内容） |

**768 → 769 差 1px**，就是「4 张全正常」和「4 张全截断」的分界。

⚠️ **必须记的一条**：`verify_ui.py` 用 **1920 / 1280 / 375** 三个视口采样 —— 1920 与 1280 都在正常区间、375 是单列也正常，**三档全部避开了这两个坏带**。所以它报 `ALL PASSED` 却漏掉了这个真实的响应式缺陷。这不是脚本写得差，是**三视口采样的固有盲区：断点之间的空档没有测到**。

→ **本任务必须同时补上中间宽度断言，否则下次换个窗口大小还会踩。**

## 3. 根因分析

### 3.1 渲染表现根因

KPI 卡的**数值被省略号截断**（`7,656…` / `3,885…`），而 `15.84` / `1.33` 正常 —— **短值不截、长值截**，说明是「可用宽度 < 文本宽度」，不是渲染错误。

### 3.2 代码逻辑根因

**根因 1 · 空档 A：5 列档没有任何中间断点**

```css
/* style.css:216（默认，>1499px） */
.row-kpi { grid-template-columns: repeat(5, minmax(0, 1fr)); gap: 16px; }

/* style.css:557 —— 唯一的收窄断点 */
@media (max-width: 1499px) {
  .row-kpi { grid-template-columns: repeat(3, minmax(0, 1fr)); }
  .kpi-val { font-size: 22px; }
  .kpi-spark { max-width: 84px; }
}
```

→ **1500–1919px 全程 5 列**，卡宽 `(W − 344) / 5` 从 314 一路缩到 235，而字号恒为 26px。**字号跟着列数走，不跟着卡宽走** —— 这是机制缺陷。

**根因 2 · 空档 B：3 列档在侧栏仍占位时就已经装不下**

769–1024px 时侧栏仍是**内联 232px**（抽屉只在 ≤768px 生效），主区只剩 537–792px。3 列 → 卡宽 152–237px，而 22px 字号需要 cardW ≥ 231.6px。

**根因 3 · sparkline 占掉近 40% 卡宽（结构性放大因素）**

```css
/* style.css:262-273 */
.kpi-card { padding: 14px 16px; display: grid;
            grid-template-columns: minmax(0, 1fr) 96px; column-gap: 10px; }
/* style.css:290 */
.kpi-spark { width: 100%; max-width: 96px; }
```

→ 卡内文本可用宽 = `cardW − 32 − 96 − 10 = cardW − 138`。**96px 的迷你走势图是"锦上添花"，却挤掉了"必须看"的数值。**

### 3.3 可算模型（用于定断点，**但需实测校准**）

```text
文本可用宽 = cardW − 32(padding) − sparkW − 10(gap)
TextNeed   = 4.8 × fontSize        # 8 字符 `7,656.98`，--mono 约 0.6em
约束：TextNeed ≤ 文本可用宽
```

**模型自检（用实测反推，吻合）**：

| 场景 | cardW | 文本可用 | TextNeed | 实测 |
|---|---|---|---|---|
| 1920 / 5列 / 26px / spark96 | 314 | 176 | 124.8 | ✅ 不截 |
| 1600 / 5列 / 26px / spark96 | 251 | 113 | 124.8 | ❌ 4px（模型 12px）|
| 900 / 3列 / 22px / spark84 | 196 | 70 | 105.6 | ❌ 41px（模型 35px）|
| 769 / 3列 / 22px / spark84 | 152 | 26 | 105.6 | ❌ 85px（模型 80px）|

→ 模型方向与量级均吻合，差异来自 `--mono` 实际字宽，**可用于定断点，但必须实测校准后定稿**。

## 4. 修复方案

### 4.1 空档 A：让字号与 sparkline **跟视口走**，而不是跟列数走

在**默认档（>1499px）**把字号与 sparkline 改成 `clamp()`：

```css
/* 替代 style.css:286 的固定 26px */
.kpi-val   { font-size: clamp(20px, 1.4vw, 26px); }

/* 替代 style.css:290 的固定 96px */
.kpi-spark { width: 100%; max-width: clamp(48px, 5vw, 96px); }
```

**模型预测**（待实测校准）：

| W | fontSize | sparkW | cardW | 文本可用 | TextNeed | 余量 |
|---|---|---|---|---|---|---|
| 1920 | 26.0 | 96 | 314 | 176 | 124.8 | +51 |
| 1700 | 23.8 | 85 | 271 | 144 | 114.2 | +30 |
| 1600 | 22.4 | 80 | 251 | 129 | 107.5 | +22 |
| **1500** | 21.0 | 75 | 231 | 114 | 100.8 | **+13** |

⚠️ **为什么不用「把 3 列断点提到 1700」**：那会让 1500–1700 变成 3 列，**丢掉 bento 的 5 列形态**（与效果图不符）。`clamp()` 能在保持 5 列的同时解决挤压 —— 更贴合设计意图。

⚠️ **1500 处余量仅 +13px（模型值）是临界点** —— 执行者必须实测：若 1500–1520 仍截断，把 `5vw` 调小（如 `4.2vw`）或把 `1.4vw` 调小（如 `1.3vw`）。

### 4.2 空档 B：**必然降列数**，不能靠缩字号

3 列档在 769px 时卡宽只有 152px，塞下「数值 + sparkline」数学上不可能（文本可用仅 26px）。

```css
/* 新增断点，只改 .row-kpi —— 不要动 768 那个块 */
@media (max-width: 1024px) {
  .row-kpi { grid-template-columns: repeat(2, minmax(0, 1fr)); }
}
```

**模型预测**：

| W | cardW | 文本可用 | TextNeed | 余量 |
|---|---|---|---|---|
| 1024 | 388 | 262 | 105.6 | +156 |
| 900 | 322 | 196 | 105.6 | +90 |
| **769** | **260** | **134** | 105.6 | **+28** |

⚠️⚠️ **关键：768 那个媒体查询块不能动。** 它同时承担**侧栏改抽屉**（`.shell { flex-direction: column }` / `#sidebar { position: fixed }` / `body.nav-open`），与 KPI 列数是**两件事**。只能**新增** 1024 断点单独改 `.row-kpi`。

### 4.3 顺带：检查是否还有同类「静默截断」元素

用户只看到 KPI，但**同类问题可能存在于任何 `overflow:hidden + text-overflow:ellipsis` 的元素**上。修复前先扫一遍：

- `.kpi-label` / `.kpi-sub` / `.mini-label` / `.mini-val` / `.mini-sub` / `.bar-name` / `.bar-val` / `.date-chip` / `.brand-mark`
- ⚠️ **排除 `.news-item a`** —— 它是**设计上就横向滚动**的（`overflow-x: auto`），不算缺陷

**扫描方式**：一次性载入页面，用 `page.set_viewport_size()` 遍历宽度（**无需重新加载**，媒体查询会即时重算，成本极低）。

### K-3 · 验证脚本增强（**本任务的核心交付之一**）

**① 完整断言视口：3 档 → 5 档**

```text
现状：1920 / 1280 / 375
改为：1920 / 1600 / 1280 / 900 / 375
        ↑ 补空档 A      ↑ 补空档 B
```

**② 新增「KPI 无静默截断」断言**（跨 12 个宽度快速扫描）

```text
WIDTHS = [1920, 1760, 1600, 1500, 1440, 1366, 1280, 1100, 1024, 900, 800, 769]
载入一次页面 → 逐宽度 page.set_viewport_size() → 检查：
  document.querySelectorAll('.kpi-val, .kpi-sub, .kpi-label')
    过滤 scrollWidth > clientWidth + 1
期望：空数组
```

**③ 断言设计原则（重要）**

- 断言**不变量**（"KPI 数值不得被截断"），**不要断死具体字号/断点数值** —— 否则调参一次就要改一次断言，最终变成"改断言让它变绿"

- 其他元素先输出**报告**（列出溢出项但不 fail），便于逐步收敛

⚠️ **先红后绿**：`clamp()` 与 1024 断点都**尚未实施**时先跑 K-3，断言必须是**红的**（`1600` / `900` 两档应报截断）。否则说明断言写错了。
