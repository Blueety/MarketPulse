# 切片

> 大需求装不进单个会话时，一个切片一个文件，放在任务目录下：`01-schema.md`、`02-api.md`。
> 拆解规则见 `tasks/README.md`。由 Agent 在只读分析后填写，人确认后再实施。

## 类型

- **类型**: `切片`
  <!-- 切片 = 「已经知道怎么做」的活；决策条目 = 「待决策的问题」。
       判据是「能不能现在就把问题精确表述出来」，见 tasks/README.md。
       改这一个词决定下面哪一节必填。 -->

## 切片必填

<!-- 类型 = 切片时填这一节；类型 = 决策条目时整节留空。 -->

- **档位**: `T? — N 文件 / N 调用方 / 行为是否有变 / 有无覆盖测试 / 预估 N 行`
- **优先级**: `P0`
  <!-- P0 / P1 / P2。优先级 ≠ 可执行性：P0 也可能被前置切片挡着，
       那时它还不是「任务前沿」（所有前置都做完的那几张）。 -->
- **完成后可以看到什么**:
  <!-- 一句可演示的话——做完这条，打开什么、看到什么 -->
- **完成标准**:
  <!-- 命令或可观察现象，不是「功能正常」 -->
- **文件范围**:
  <!-- 这次要改 / 新建哪些文件，写路径即可 -->
  <!-- 与 plan.md 的「相关文件」不同：那个是任务级，这个是切片级。
       两个切片要改同一个文件，通常说明切片切得不干净，值得回头看一眼。 -->
- **被谁挡**: `无`
  <!-- 只写真正卡住它的前置切片编号（`01`、`01, 02`），没有就写「无」。 -->
- **状态**: `pending`
  <!-- pending / in_progress / completed -->
- **主要提交**: ``
  <!-- 完成时回填工作提交的 SHA。本文件的状态更新在它之后的提交里，
       所以不会出现「自己写自己的哈希」。 -->
