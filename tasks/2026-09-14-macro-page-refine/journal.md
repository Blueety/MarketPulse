## 3. K-1 · D1（深色模式失效）

**根因**：`macro.html` 里 `<html data-theme="light">` 是**默认值**，而 head 内联脚本只处理"存储为 light 的分支"：

```js
if (localStorage.getItem("mp-theme") === "light") { setAttribute("data-theme", "light"); }
```

存储为 `dark` 时**没有任何代码把 dark 写回** → 属性停在 `light`。`macro.js` 里虽有 `getTheme()`，但**只在点击切换按钮时**被调用（`applyTheme` 从未在 init 阶段执行）。首页之所以正常，是因为 `app.js` 在模块顶层就调用了主题初始化。**时序**：用户从首页（dark）点侧栏进 `/macro` → 新文档、HTML 默认属性生效、无人写 dark → 页面全白。

**改法（两处同口径）**：
1. `macro.html` head 内联脚本：显式应用**存储到的任何合法主题值**（`light` / `dark`），保留 `data-theme="light"` 作为无 JS 兜底；
2. `macro.js`：抽出 `applyTheme(theme)` 并在**模块顶层立即调用一次**，点击切换也走同一函数（避免两套写法再次分叉）。

**证据**：见 §1 D1 行；断言 `M-1 / M-1b / M-2` 三视口偏好下与首页完全一致。

## 4. K-2 · D2 的真相：**过滤未实现**（不是标注写错）

先按 plan §5-K-2 要求查清事实（不猜）：

- `web/app.py` 的 `compute_macro_correlation` **不带任何 `|r|` 阈值参数**（固定返回 6 对；`r=None` 只在样本不足时出现）→ **后端没有过滤，前端也没做过滤**，标注里的「≥ 0.5 才列出」是**纯口头承诺**。
- 实测 6 对的最大值 0.47 → 当前数据下**本来就不该列出任何一对**。

**改法**：过滤在前端实现，且**过滤规则与标注文案由同一组常量生成**（单一事实来源）：

```js
var REL_MIN = 0.5;        // 显著阈值
var REL_TOP = 3;          // 默认最多列 3 条（PRD 要点 6）
var REL_FALLBACK = 2;     // 无显著对时兜底 2 条（不留空卡，但不假装显著）
```

- 有显著对 → 「\|r\| ≥ 0.5 的显著对，显示前 N 组 · 共 6 组」；
- 一条都没有 → 「**当前无显著对（\|r\| 均 < 0.5）**，显示最强的 2 组 · 共 6 组」+「查看全部 6 组 →」；
- 展开后标注同步变成「已展开全部 6 组」（否则又制造一次"标注说 2 组、屏幕 6 行"的不一致）；
- 容器加 `data-rel-mode="significant|fallback"`，让**过滤口径可被验收断言**（不再只靠读文案）。

`n=251` 保留为次级信息（plan 要求）。

## 7. 偏离计划的地方（诚实清单）

1. **历史模块「已持续 X 天」→ 改为「近 N 个交易日中 M 天（X%）」**（plan §3.3 要点 7）。
   原因：`/api/macro` 的 `history_regime` 给的是"近 30 个交易日各状态各占几天"，**没有逐日序列** → 单靠前端**算不出"连续多少天"**，写出来就是编造。改为只用接口支持的口径，并把「当前：Risk-On」置顶（原诉求的"突出当前"已达成）。
2. **核心变量「状态词」用日变化分档**（明显/小幅走强走弱、基本持平），阈值（±0.2 / ±1）是**工程取值**，卡头写明"状态词按日变化分档" —— 不引入任何新数据，只把已显示的 `change_pct` 说成人话。
3. **因子「市场影响」= 前端静态映射**（`FACTOR_ASSETS`），方向取服务端已给的 `impact` 正负；卡头标注「影响资产为前端静态映射」—— **不是模型输出，也不是预测**。
4. **顺手修掉验收脚本里两族"写死日期"的断言**（原本就是红的，与本次改动无关，见 §8）。
5. **两列合流断点 1299 → 1023**（plan 只说"让 1280 保持两列"，未指定新断点值；取 1023 与首页 900/1024 档的既有断点体系一致）。
