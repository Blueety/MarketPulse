# 任务目录

## 任务子目录

每个复杂任务创建一个子目录：

```
tasks/<日期>-<简述>/
  prd.md          需求文档
  plan.md         实施计划
  journal.md      执行日志
```

## 模板目录

`tasks/_template/` 里有 prd.md、plan.md、journal.md 的空白模板。新建任务时从这里复制：

```bash
cp tasks/_template/prd.md tasks/2026-08-04-add-login/prd.md
cp tasks/_template/plan.md tasks/2026-08-04-add-login/plan.md
cp tasks/_template/journal.md tasks/2026-08-04-add-login/journal.md
```

## 什么时候建任务目录

用 `docs/agents/任务分级.md` 的 6 条信号判定，不要凭感觉：

| 信号 | 免检线 | 升级线 |
|---|---|---|
| 要动的文件数 | = 1 | ≥ 4 |
| 受影响调用方数 | 0–1 | ≥ 2 |
| 是否动公开接口 / 数据形状 | 否 | 是 |
| 该路径有无现存测试 | 有且当前能跑通 | 无 |
| 行为是否变化 | 只改文案 / 格式 / 注释 / 日志文本 | 是 |
| 预估 diff 行数 | ≤ 20 | > 200 |

> 这张表是速查。`怎么量`一列和全部判据细则在 `docs/agents/任务分级.md`，两处冲突时以那份为准。

- 全部落在免检线内 → **T0**：不建目录、不写 plan，直接改完跑测试
- 有信号落在升级线 → 建目录
- 升级线 + 涉及公开接口或跨模块 → 建目录，并且需要 seam 确认
- 修 bug 且现象无法稳定复现 → **不看规模，建目录并按 T3 走**

## 大需求拆成多个任务

一个 prd 装不进单个会话时，拆成多个任务文件，每个声明它被谁挡着：

```
tasks/2026-08-04-add-login/
  prd.md            # 总目标
  01-schema.md      # 被谁挡: 无（可立即开始）
  02-api.md         # 被谁挡: 01
  03-ui.md          # 被谁挡: 02
```

规则：

- 每个切片是**垂直**的（贯穿 schema / API / UI / 测试），不是一个横向的层
- 每个切片做完都能独立演示或验证
- 「被谁挡」只写真正卡住它的前置切片，没有就写「无」
- 任何前置都做完的切片，就是下一个该做的

## 命名规范

```
tasks/2026-08-04-add-login/
tasks/2026-08-05-fix-null-pointer/
```

用 `日期-简短英文描述`，不要用中文或空格。
