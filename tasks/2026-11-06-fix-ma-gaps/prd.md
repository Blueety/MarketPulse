# 首页点位视图均线被缺口吞点（MA60 拉成一条长直线）

## 档位

- **档位**: T1 — 3 文件 / 0 调用方 / 行为有变（点位图均线形状）/ 有覆盖测试（`verify_ui.py` TM-10，本次新增）/ 预估 40 行

## Goal

点位视图（`#trend` 的「点位」）上 MA20 / MA60 必须在每个有价格数据的交易日都出点；现状是 `movingAvgPts` 要求「最近 win 个**日期槽位**内零缺失」才出点，而 `/api/history` 的 `dates` 是多市场共享的交易日轴（上证 299 槽位里 18 个 `null`），于是：

- MA60 在 1Y 窗口只剩 **49 个点**（应为 189+），剩余点之间被 Chart.js 用一条直线相连 —— 用户 2026-11-06 反馈「紫色的均线怎么中间直接横过去了，都没波折」（那段直线实际是 2025-12-31 → 2026-07-29 的一条 7 个月长弦）；
- MA20 同样被吞到 154 点（应为 262）。

修法：窗口口径改成「最近 win 个**有效观测**」（滚动维护最近 win 个非空值的和），缺口不再吞点。

## 验收标准

1. Given 点位视图选中任一指数，When 切到 1Y / 3Y 档，Then MA20 的数据点数 == 该窗口内「有值且非周末」的交易日数 − 19，MA60 == 交易日数 − 59（不允许被 `null` 缺口吞点）。
2. Given 上图同一帧，When 逐点比对 `Chart.getChart('#chart-main').data.datasets[1..2]` 与独立预言机（滚动均值，窗口 = 最近 win 个有效观测），Then 每个点的 `x`（日期）与 `y`（均值，误差 ≤0.05）完全一致。
3. Given 3Y 档的上证，When 观察 MA60 曲线，Then 相邻数据点之间不再出现跨多月的直线段（最大相邻间隔与该指数价格线一致，即节假日 11 天以内）。
4. Given 本次改动，When 跑 `scripts/verify/verify_ui.py`，Then 新增 TM-10 通过，且其余断言数量与改动前持平（不引入新红）。

## 这一版要验证什么

- **假设**：用户看到的「直线段」是丢点造成的，不是均线算法口径错（不是应该按日历日而是应该按交易日）。
- **值得继续**：改成「最近 win 个有效观测」后，MA 点数 == 该窗口有效观测数 − win + 1，且逐点等于独立预言机。
- **该停**：改完仍出现长直线 —— 那说明 Chart.js 侧还有 spanGaps / 点集有序性问题，需换方向查。
