## 2. K-1 / K-2 改动与实测校准

### 2.1 ⚠️ 与 plan §4.1 的关键差异：**必须同时改「网格轨道」**

plan §4.1 只写了改 `.kpi-spark { max-width: clamp(48px, 5vw, 96px) }`。**实测/读码确认那样改无效**：
`.kpi-card` 的网格轨道是**硬编码** `grid-template-columns: minmax(0, 1fr) 96px`（`style.css:273`）——
`max-width` 只把 spark **元素**缩窄，**轨道仍占 96px**，文本列一个像素都不会多。

故实际改为：把宽度提成自定义属性，**轨道与元素共用同一变量**：

```css
.kpi-card {
  --kpi-spark-w: clamp(48px, 5vw, 96px);          /* 新增：跟随视口 */
  grid-template-columns: minmax(0, 1fr) var(--kpi-spark-w);   /* 轨道：原固定 96px */
}
.kpi-val   { font-size: clamp(20px, 1.4vw, 26px); }            /* 原固定 26px */
.kpi-spark { max-width: var(--kpi-spark-w, 96px); }            /* 原固定 96px */
```

### 2.2 空档 B：新增 1024 断点（只动 `.row-kpi`）

```css
@media (max-width: 1024px) { .row-kpi { grid-template-columns: repeat(2, minmax(0, 1fr)); } }
```

**✅ 未动 `@media (max-width: 768px)` 块**（它同时管侧栏抽屉：`.shell` 方向 / `#sidebar` fixed /
`body.nav-open` —— 与列数是两件事）。

### 2.3 其余改动

- 删除 `@media (max-width: 1499px)` 里的 `.kpi-spark { max-width: 84px }` —— 它已成**死规则**
  （≤1499 时 `5vw ≤ 75px < 84px`，永远命中不到），留着会与变量两处不同步。
- `.kpi-val` 的 `clamp()` 只在 **>1499** 生效（≤1499 由该断点的 22px 覆盖、≤480 由 18px 覆盖）——
  正是空档 A 需要的区间。

## 3. K-3 验收脚本增强

① **完整断言视口 3 → 5**：`VIEWPORTS = [(1920,1080), (1600,900), (1280,720), (900,800), (375,812)]`
（补 1600 = 空档 A、900 = 空档 B）。`GLASS_RANGES` 按**主题**取区间、与宽度无关 → 新增视口对玻璃判据无副作用。

② **新增 `assert_kpi_no_truncation`（KY-1~KY-3）**：单次加载 + 逐宽度 `set_viewport_size()`（不重载），
扫 `.kpi-val / .kpi-sub / .kpi-label` 的 `scrollWidth > clientWidth + 1`；其它 ellipsis 元素**只报告不 fail**；
`.news-item` 内元素显式排除；KY-3 断言"确实扫满 12 个宽度"（防空扫描假绿）。

③ **断言只断不变量**（plan R2）：断言的是「KPI 不得被省略号截断」，**没有**断死任何字号/断点数值 ——
所以以后调 `clamp()` 系数不需要改断言。

④ **先红后绿**：未改 CSS 时先跑 → KY-1 在 1600/1500/900/800/769 五档**红**（见 §1）；改完 → 12 档全绿。

## 4. 过程中的一次外部依赖抖动（已处理）

改完 CSS 首跑时，出现 **2 条新红**：`MX-11 / MX-11b`（宏观页经济数据「数据暂缺」）。
取证：

- 页面 **console error = 0** → `/api/econ` 请求本身成功（HTTP 200），只是 payload 的 `as_of` 为 `null`；
- 直测服务端：`fetch_econ_series()` 正常（`as_of=2026-08`、4 序列、1.9s），端点直测 2.1s 正常 → **不是 BLS 当日额度**（限额 25 次/日）；
- → **判定：服务端那一次 BLS 调用瞬时失败**（端点按设计**不缓存失败结果**，所以会自愈）。

**处置**：给 MX-11 前加**一次重试**（`/macro` 重载会再次触发取数）—— **判据不放松**（仍要求显示「YYYY年M月」），
只是不把外部 API 的一次网络抖动判成页面缺陷。复跑即绿（本次未触发重试）。
