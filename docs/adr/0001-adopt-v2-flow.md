# 0001 采用「档位 + 闸门」的流程层

本项目原来的流程只有步骤清单（只读分析 → 计划 → 实现 → 验证 → 日志），没有退出门槛，于是两类失败反复出现：小改被仪式拖累，修 bug 在没有可复现信号时就开始猜根因。2026-09-26 起采用 project-scaffold 的 v2 流程层：规模轴（T0–T3）与类型轴（加功能/可复现 bug/不可复现 bug）分开判档，取更严者；修 bug 进根因假设前必须先有一条已实跑、能对**这个** bug 变红的命令（闸门 A）；提交前 grep 清 `[DEBUG-` 埋点并删一次性脚本（闸门 B）；测试只在事先约定的 seam 上写。

替代方案是继续用「步骤清单」轻流程（少写文档、上手快），被否掉的原因是它无法阻止「无信号猜根因」和「测试写在哪全靠感觉」这两类失败，而这两类恰恰是最贵的返工来源。代价是每次任务多一行档位声明与（T2 以上）一次 seam 确认。
