# 重构

> 适用于类型轴 = 重构的任务：**行为不变，只改结构**。

## 安全网（动手之前必须有的东西）

重构的判据是「行为不变」。**没有能证明行为没变的测试，就没有判据**——你只是改完看着还行。

1. **相关路径有能跑通的测试吗？** 有就直接用。
2. **没有就补 characterization test**：把代码**当前的实际行为**记下来，不是你以为它该有的行为。
   - 输入输出、边界值、异常路径各来一条
   - 古怪行为也要锁住——它可能是有人在依赖的既有行为
   - 这类测试的期望值来自**实跑结果**：跑一遍，把输出记下来当期望值
3. 安全网跑绿之后，才开始改结构。

**跑不了的测试不是安全网。** 慢、flaky、要人工参与的，先按 `skills/bug-fix/SKILL.md` 的「把回路收紧」处理。

## 发现行为其实不对怎么办

**停下来。** 那不是重构，是修 bug 或加功能——转去对应的 skill，别混在一个改动里。

混在一起的代价：diff 里既有结构变化又有行为变化，审查时分不清哪处是故意的，回滚也没法只回滚一半。

## 循环

一次一小步，每步跑一次安全网：改一小块结构 → 跑安全网 → 绿就继续，红就改回去。

不要「全部改完再跑测试」——那时候已经分不清是哪一步弄坏的。

## 什么算「结构」

- 抽函数 / 内联、改名、搬移
- 消除重复、拆长函数、把散落的逻辑收拢
- 换内部数据表示（不换对外形状）
- 引入 seam（接口位置）以便将来替换实现

判据：**调用方看得见的东西不变**——对外签名、错误模式、不变量、可观察输出，一个都不动。

## 不要顺手做的事

- 不要顺手加功能，哪怕一行
- 不要顺手改与结构无关的格式（那是 lint 的事）
- 不要顺手升级依赖
- 不要在没有安全网的区域动刀

## 和别的 skill 的分工

- **`skills/tdd/SKILL.md`**：加新行为时用（红 → 绿）。重构**不在**那个循环里，但重构需要它产出的测试当安全网。
- **`skills/bug-fix/SKILL.md`**：行为要变时用。重构途中发现行为不对，转过去。
- **`skills/pre-review/SKILL.md`**：改完之后审查。Standards 轴看结构是不是真的变好了（重复代码 / 发散式变化 / 霰弹式修改这类坏味道）。

## Output

- 安全网是什么：哪几个测试 / 命令，补了哪些 characterization test
- 结构改了什么，以及**行为没变**的证据（安全网跑绿的实际输出）
- 顺带发现的行为问题（如果有）——单列，不在这次改
