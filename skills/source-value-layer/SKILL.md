# 接入外部数据源 / 新增字段层：五步取证流程

适用：往 `src/` 加一个外部源抓取器，或给既有链路加一维数据（值、单位、分档、口径）。
不适用：纯前端改动、纯算法改动。

**总纪律：任何"源里有 X"的结论都必须由本机实测得出，并写明实测条件（直连/代理、时间、条数）。**
本项目已多次因"文档说有"而踩坑（MiMo 端点 DNS 失败、BLS `.ics` 403、TradingEconomics guest 410）。

## 0. 前置：先确认"缺的到底是什么"

按**层**定位，别急着改渲染层：

| 层 | 检查点 | 判据 |
|---|---|---|
| 数据模型 | `storage._SCHEMA` 的表列（`PRAGMA table_info`） | 表里**根本没有这一维** ⇒ 是能力缺口，不是 bug |
| 组装层 | `timeline.build_timeline()` 的 `item = {...}` | 该处是**逐键显式构造** ⇒ 表里加了列也不会自动透传，必须显式加键 |
| 渲染层 | `web/static/*.js` 的渲染函数 | 只有到这一步才是"字段被丢掉" |
| **采集层** | 解析函数的返回 dict | 若源里就没有 ⇒ **前面三层全都不用看** |

> 本次实例：`econ_events` 只有 9 列且无 `actual`，两个源（Fed HTML / 镜像 `.ics`）是纯日程源
> ⇒ 根因在**采集层**，前端"美化"是无效方向。

## 1. 源可达性 + 字段可用性探针

探针落 `%TEMP%`（**不落仓库**），逐个源打印：HTTP 码 / 耗时 / 字节数 / content-type / JSON 结构 / 样本字段。

必查项（缺一项就不算验证过）：

- **直连 AND Clash 7890 代理分别测**（本项目两条链路行为不同）。
- **值三维是否齐全**：`actual` / `forecast` / `previous`——只要缺 `forecast` 就回答不了"与预期差多少"。
- **单位与口径**：有没有 `unit`；**有没有"看着像但语义不同"的陷阱**。
  本次实例：TradingView 的美国 `CPI` 的 `actual` 是**指数水平 334.98**，不是同比% —— 直接显示会误导用户。
- **请求头**：有些端点必须带 `Origin`/`Referer` 才返回数据（TradingView 要 `origin: https://www.tradingview.com`）。
- **单请求上限 / 分页**：用"全年 vs 单季"两个窗口对照，**条数相等即打满上限**。
  本次实例：2019/2021/2023/2025/2026 全年**都恰好 2000** ⇒ 上限 2000，必须按月分段。
- **历史深度**：拿 1~2 年前的窗口确认值还在（决定能否回填）。

被排除的源也要记进方案（含排除理由），否则下次会有人再试一遍。

## 2. 三段对账（解析类源必做）

`原始条目数` vs `解析成功数` vs `去重后数` 三个数打出来。
不相等就必须逐块对账（本项目 Fed 页曾因"月份混用全名/缩写"静默漏 3 场会议）。
过滤规则（`CANCELLED` 等）要**两条路径都查**：`STATUS` 字段与标题后缀是独立的。

## 3. join 命中率基线（决定方案可行性的唯一硬指标）

拿**骨架侧的真实数据**（本项目 = `data/marketpulse.db` 只读连接 `file:...?mode=ro`）去对**值侧**：

```
对每条骨架行：按 (转换后的日期, 归一化 kind) 找值侧 headline 行，tolerance 从 0 开始试
输出：逐条 命中/未命中 + 用了多少容差 + 值
输出：命中率，并按原因给未命中分类
```

- **报告必须区分"过去事件"与"未来事件"的命中率**。本次：过去 **33/33（零容差）**，
  未命中 8 条**全部**是未来（尚未公布）⇒ 结论是"**不需要 ±N 天容差**"，
  这一条直接把实现复杂度砍掉一大块（容差反而会引入张冠李戴）。
- 归一化映射要**表驱动写死**，且映射表本身用"近 13 个月标题枚举"（`Counter` 计数）取证：
  本次实测出 `CPI` 无同比行、`GDP` 有 Adv/2nd Est/Final 三行需按期次选、`PPI MoM` 才是 headline。
- **同日同 kind 多行是真会发生的**（政府停摆顺延）：本次 2025-12-16 两条 `Non Farm Payrolls`。
  必须定择优规则，并把这条真实日期写成断言。

## 4. UI 尺寸预测量（方案里要动前端时）

启动真实应用（`venv/Scripts/python -m uvicorn web.app:app --port 8000`）+ Playwright 五视口
（1920/1440/**1280×720**/768/**375**），测：

- 目标行的 `box-sizing` / `display` / **`flex-wrap`** / `gap` / `padding` / `clientWidth` / `clientHeight`；
- **行尾剩余宽度** = `row.left + row.clientWidth − 最右子元素.right`（注意减掉 `gap`）；
- 拟插入文本的实测宽高（用真实字号，别用继承的 16px 估）；
- **增量测量必须"原地注入"**：`row.appendChild(span)` → 量 → `span.remove()`。
  **不要克隆行再插入** —— 克隆会多出一个 flex 兄弟项，污染 `.tl-day` 高度（本次第一版就报出假的 `dayH_delta=12.08`）。

关键判据：`flex-wrap: wrap` 的行**放不下就折行而不是溢出** ⇒ 加内容不会破"无横向溢出"断言，
但会**增高卡片**。这两件事必须分开写在方案里。

## 5. plan.md 里必须出现的三张表（缺一张就是"推演方案"）

1. **候选源实测对照表**：源 / 实测结果（HTTP 码+耗时+字节） / 值三维有无 / 结论（含排除理由）。
2. **对齐命中率表**：逐条命中情况或至少"命中数/总数 + 容差分布 + 未命中原因分类"。
3. **多尺寸布局实测表**：视口 / 行可用宽 / 行尾剩余 / 原行高 / 加值后行高 / 是否折行 / 是否溢出。

外加两条必写：**迁移顺序**（列先行、代码后行；`CREATE TABLE IF NOT EXISTS` 对既有库**不加列**，
必须写幂等 `ALTER TABLE ADD COLUMN`）与**写入语义**（新值必须 preserve：非空才写，
绝不用 `null` 抹掉已落库的值，对齐 `upsert_history_rows(preserve_existing=True)`）。

## 6. 落盘与上线链（本项目特有）

- `data/marketpulse.db` **已被 git 跟踪**（`git ls-files data` 可验）⇒ 值落进 `.db` 后，
  cron 的 `git_ops.auto_commit_push`（白名单含 `data/`）会推上去，Railway 直接读到。
- 风险：`-wal` 残留会导致提交的 `.db` 不含新行。保险做法是 push 前调 `storage.wal_checkpoint()`。
- 本地验证真跑抓取脚本用 `AUTO_PUSH=0`，真跑**限一次**（会触发 Railway 重部署）。

## 7. 坑清单（本次实测，全部会静默出错）

| 坑 | 症状 | 判据 |
|---|---|---|
| UTC 日期直接当匹配键 | 00:00–04:00Z 的事件错一天（当前 8 类恰好在 12:30Z–19:00Z 不触发 ⇒ **将来扩类型必爆**） | 一律先转目标市场时区再取日期 |
| 值侧用了 16px 继承字号估宽度 | 预算高估、误判"会折行" | 预算必须用**拟用字号**实测 |
| 克隆行做 what-if | `dayH_delta` 假值 | 原地注入 + 移除 |
| 断言标签含 GBK 外字符（`⇒`） | 整个 `verify_ui.py` 中途 `UnicodeEncodeError` | 断言标签只用 GBK 内字符 |
| 只测浅色/单主题 | 新增色值在深色下不可读 | 新增样式只用既有 token，不写死色值 |
