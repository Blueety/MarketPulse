# Research（外查）

> 与 `bug-fix` 的分工：那个查**你自己的代码**为什么坏；这个查**外面的世界**是怎么回事。

## 何时用

下一步卡在「得先知道外面怎么规定 / 怎么表现」：

- 第三方 API 的行为、认证方式、限额
- 规范 / 标准 / 官方文档**原文**到底怎么写
- 某版本是否真的支持某个特性
- 数据源是否停更、口径变了没（本项目常见）
- 合规、政策、对方接口的硬约束

判据：**你会因此停下主线程去读文档** ⇒ 这就是该派出去的活。

## 何时不用

- 想知道「我们库里能不能这么做」→ 那是原型 / 直接读代码，不是外查
- 产出的是一条**决策**而不是一个**事实** → 决策进 `docs/adr/`，不进研究文件
- 两行提示词就能解决的小问题 → 直接问。研究的价值是**留证据**，不是替代一次搜索

## 做法

1. **一次只问一个窄问题**：范围写死（一个 API、一个行为、一条版本声明）。「研究一下 XX」这种宽问题必定回垃圾。
2. **派出去**：用 harness 的子 agent 机制在后台跑（omp：`task` / `scout`），主线程继续干别的。同一个问题**只派一个**；子 agent 不许再往下派（上游有已知自复制 bug：一次研究烧过 ~450k token）。
3. **只认一手来源**：官方文档、源码、规范、一方 API 的真实响应。**每条论断带链接**。如果链接落到的是「别人转述这个 API」的文章，这轮就是失败的，回去找本源。
4. **落一份文件**（不要只在对话里答）：
   - **位置**：`tasks/<日期>-<简述>/research/<slug>.md`；不属于任何任务时落 `%TEMP%`，并在回话里给出路径
   - **结构**：`# 问题` → `## 结论`（一两句，够你做决定）→ `## 证据`（每条带链接 + 摘录）→ `## 未确认 / 边界`（查不到的部分明说）
   - 一份文件一次研究，不要追加成日记
5. **回话只说三件**：文件路径、结论一句话、哪些还没确认。

## 纪律

- **过期即删**：研究文件记的是「那天的事实」。要长期留下的是**结论**——结论进 `CONTEXT.md`（术语 / 口径）、`docs/adr/`（决策）、`docs/pitfalls.md`（坑），**不是这份文件本身**；下一轮读到的过期研究比没有更糟。
- 不把「文档说支持」当成「我们能跑通」——后者要原型或实测。
- 探针脚本、抓下来的原始响应落 `%TEMP%`，不落仓库。

## 完成判据

- [ ] 问题窄到一句话
- [ ] 每条论断都能顺链接落到官方文档 / 源码 / 规范，而不是转述
- [ ] 文件已落盘，路径已告知用户
- [ ] 用户**只看这份文件**就能做掉原来卡住的那个决定
